:::note[Workers and Fleet Agents are different]
Workers are reusable task definitions that run inside an HQ session. [Fleet Agents](/hq/products/fleet-agents/) are persistent, cloud-hosted teammates with their own identities, managed runtimes, company access, and communication channels.
:::

## Worker Types

| Type | Purpose |
|------|---------|
| CodeWorker | Implements features, fixes bugs, refactors |
| ContentWorker | Drafts content, maintains voice consistency |
| SocialWorker | Social media posting, engagement |
| ResearchWorker | Analysis, market research, competitive intel |
| OpsWorker | Reports, monitoring, automation |
| PersonaWorker | A worker that runs as a chat bot, such as the Setup bot |
| Library | Shared utilities (not directly executable) |

HQ ships 43 workers in `core/workers/public/`. The full list, with each worker's type and description, is `core/workers/registry.yaml`. HQ regenerates that file from each `worker.yaml`, so don't edit it by hand.

## Worker YAML Schema

Every worker is defined by a `worker.yaml`:

```yaml
worker:
  id: my-worker
  name: My Worker
  type: CodeWorker
  version: "1.0"

execution:
  mode: on-demand        # on-demand | scheduled | event-triggered
  max_runtime: 30m

context:
  base:
    - core/knowledge/public/Ralph/   # Knowledge to load
  dynamic: []
  exclude: []

verification:
  post_execute:
    - tests-pass
    - no-lint-errors
  approval_required: false

tasks:
  source: companies/my-company/projects/my-project/prd.json

output:
  destination: workspace/reports/
  format: markdown

instructions: |
  Multi-line instructions for the worker...
```

## Creating Custom Workers

Use `/newworker` to scaffold:

```
/newworker
```

The wizard asks for:
1. Worker ID and name
2. Type (CodeWorker, ContentWorker, etc.)
3. Skills (name + description for each)
4. Knowledge context paths
5. Execution rules

It then asks whether the worker belongs to one company or ships with HQ, and generates it at `companies/{co}/workers/{id}/` or `core/workers/public/{id}/`:
```
{id}/
├── worker.yaml
├── skills/
│   ├── skill-one.md
│   └── skill-two.md
└── README.md
```
