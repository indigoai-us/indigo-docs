Indigo is an early-stage company. This page states our compliance posture honestly: what we align to today, what we are actively building, and what is planned. We do not claim certifications we have not earned.

## Framework posture (at a glance)

| Framework | Status | What this means |
|---|---|---|
| SOC 2 (Type II) | Designing toward; not yet audited | Our controls are designed to align with the Trust Services Criteria (Security, Availability, Confidentiality). We have not completed a SOC 2 examination and do not claim to be "SOC 2 compliant." |
| ISO 27001 | Not certified | Considered as a later milestone after SOC 2. |
| ISO 42001 (AI management) | Monitoring | Increasingly requested of AI products; under evaluation given HQ is an AI platform. |
| GDPR | Supported | We design data handling to support GDPR obligations and can sign a DPA with EU Standard Contractual Clauses. (Note: customer data currently resides in the US — see residency below.) |
| CCPA/CPRA | Supported | We support service-provider obligations and data-subject requests. |
| NIST CSF | Reference framework | Used as an internal reference for control coverage. |

:::note[Honesty principle]
"Compliant" and "certified" are reserved for states we can evidence with a report or certificate. Where we are not there yet, we say "designed to align with," "in progress," or "planned," with target timing where we can commit to it.
:::

## What is already in place

These controls are implemented today and are documented in the supporting security pages:

- Tenant isolation — dedicated per-tenant S3 bucket; a dedicated KMS key for each new vault; per-request scoped STS credentials; test-enforced in CI. ([Tenant Isolation](/hq/security/3-tenant-isolation/))
- Encryption at rest — SSE-KMS with a dedicated customer-managed key and annual rotation for new vaults; some existing vaults use a shared Indigo-managed KMS key or SSE-S3 until re-keyed. ([Data Security & Encryption](/hq/security/4-data-security-encryption/))
- Encryption in transit — enforced TLS; storage denies non-TLS requests.
- Authentication — Cognito with Google and Microsoft federated sign-in (OIDC); native self-registration blocked; MFA enforced at the IdP; JWT authorization on every route. ([Identity & Access Management](/hq/security/5-identity-access-management/))
- Network isolation — the vault data plane runs in a dedicated VPC with private subnets, no NAT, VPC endpoints, and private databases. Services that call third-party APIs run in separate networks. ([Infrastructure & Network Security](/hq/security/6-infrastructure-network-security/))
- Audit logging — application audit trail of credential issuance and admin actions; CloudTrail management events with log-file validation; best-effort S3 server access logs on vault buckets.
- Secure SDLC — code review; lockfile-pinned dependencies; CI type-check/lint/test plus blocking cross-tenant isolation tests; Dependabot and gitleaks secret scanning on the hq-pro, hq-cli, and hq-desktop-app repositories. ([Application Security & SDLC](/hq/security/7-application-security-sdlc/))
- Signed software — signed desktop auto-updates. Developer ID signing and notarization depend on the release workflow's signing setting ([Application Security & SDLC](/hq/security/7-application-security-sdlc/)).
- Capability-based sharing — encrypted, single-use, time-limited, scope-pinned share tokens.
- Subprocessor management — maintained, dated subprocessor list with a no-model-training stance. ([Subprocessors](/hq/security/2-subprocessors/))
- Vulnerability disclosure — published policy and `security@hqforwork.com` contact; `security.txt` (RFC 9116) at `https://hq.computer/.well-known/security.txt`. ([Vulnerability Disclosure](/hq/security/11-vulnerability-disclosure/))
- Public status page — [status.hqforwork.com](https://status.hqforwork.com).

## Data residency

HQ's primary stores are in AWS `us-east-1` (United States). Some subprocessors process data in other locations, and Bedrock cross-region inference may process AI requests in other AWS regions; see [Subprocessors](/hq/security/2-subprocessors/). For EU customers, transfers are handled under appropriate mechanisms (e.g., SCCs in a DPA). EU/other-region data residency is not offered today; it can be discussed for specific enterprise needs.

## Privacy and data-subject rights

- We support data export and deletion on request (see the retention and deletion section of [Data Security & Encryption](/hq/security/4-data-security-encryption/)).
- We will sign a DPA addressing controller/processor roles, subprocessor change notice, security measures, breach notification, audit rights, and deletion/return on termination.
- For privacy inquiries and data-subject requests: security@hqforwork.com.
