> **Fleet agents answer in Slack from their own machines.** Connecting an agent to Slack mints a dedicated Slack app for that one agent, installs it into your workspace, and routes every mention to the agent's inbox. There is nothing to run locally — the agent's box does the work.

## Connect an agent to Slack

1. In the HQ console, open your company's **Team** (or **Agents**) page and open the agent's settings (the gear on its row).
2. Under **Slack**, choose **Attach Slack**. HQ mints the agent's Slack app and hands you an install link.
3. Approve the Slack authorization screen. You need permission to install apps in the workspace; some workspaces require Slack-admin approval first.
4. You'll land on a confirmation page — the agent is live as soon as the install completes.

Re-running **Attach Slack** on an already-connected agent is safe: it re-registers the app's event delivery and refreshes its credentials. It's also the standard repair step if the agent stops hearing messages (see [Troubleshooting](#troubleshooting)).

## Add the agent to a channel

Slack agents are **apps**, and apps join channels differently than people:

1. Open the **channel** where you want the agent. It must be a channel (public or private) — an agent can't be added to a group DM this way.
2. Type a message that `@`-mentions the agent by name (for example `@Izzy hello`) and send it.
3. Slack will tell you the app isn't in the channel and offer to **add it** — confirm, and the agent is in.

You can also use the channel's **Settings → Integrations → Add apps** menu. The `/invite @name` command is for *people*; depending on the workspace it may not offer apps at all, so the `@`-mention flow above is the reliable path.

## When the agent replies

- **Channel mentions** — `@`-mention the agent in any channel it's in and it answers **in-thread**. The first reply after a cold start can take ~30 seconds; you'll see a 👀 reaction and a typing indicator while it works.
- **Threads it's part of** — once the agent is mentioned in a thread (or starts one), it follows that thread and answers follow-ups without needing another mention.
- **Top-level channel chatter** — the agent does **not** respond to messages that don't mention it. Mention it once per conversation to pull it in.
- **Direct messages** — DM the agent's app directly; access can be restricted to specific teammates by the agent's configuration.

## When the agent acts as you (owner delegation)

Every agent has one or more **owners** — starting with whoever created it. When a recognized owner messages their agent in Slack, the agent acts with **that owner's vault access** (a strict subset of it) instead of its own default identity. Ask it to pull a file only you can see and it can; a teammate who isn't an owner gets the agent's own baseline access instead. This is on by default for every company.

A few things worth knowing:

- **Owners are managed in the console.** Open the agent's settings and use the **Owners** panel to see the current owners, invite another owner, or revoke one. The Owners panel is visible only to active owners — if you don't own the agent, you won't see it.
- **The agent only ever borrows *your own* access.** It never combines several owners' permissions, and it never exceeds what you can already reach yourself. A non-owner never triggers delegation.
- **If the agent can't recognize who you are, it falls back to its own identity** rather than guessing — so delegation simply doesn't kick in until your identity is linked or safely matched (below).
- **A company can turn delegation off.** It's enabled everywhere by default, but a company-level control can disable it; with delegation off, the agent always acts as itself.

### Connect your personal Slack identity

The most reliable way for an agent to recognize you is to connect your personal Slack identity for the workspace where you talk to it. HQ prompts you when that connection is missing:

- after you create an agent;
- after you accept an invitation to become an agent owner; and
- in the agent's settings while you are an active owner.

Choose **Connect Slack** in any of those prompts and approve the Slack authorization screen for the agent's workspace. The prompt never blocks agent creation or owner approval, and you can also connect later under **Personal Integrations**.

The connection is workspace-specific. If you authorize a different workspace, HQ tells you which workspace the agent expects and lets you reconnect. If the saved connection needs attention, the same prompt offers a reconnect.

As a fallback, HQ can safely match a verified Slack email to the same email on an active company membership. That fallback is deliberately narrow; an explicit personal connection remains the primary path and is required when the emails differ. If neither path can verify you, the agent acts as itself rather than guessing.

## Troubleshooting

**The agent stopped answering mentions it used to answer.**
Check the agent's Slack diagnostics in the console (agent settings → Slack). If the last-received-event time is stale while the agent's runtime shows healthy, Slack has likely paused event delivery to the app — this can happen after a window of failed deliveries (for example during an outage). Re-run **Attach Slack** and approve the fresh install link; that re-verifies the webhook and turns delivery back on. After a re-install, add the agent to your channels again (see above) — a re-minted app is a new Slack app membership-wise.

**The agent never answers one specific person.**
If the agent has an allowed-callers list, senders not on it are dropped silently by design. Check the agent's caller settings in the console.

**The reply takes a long time.**
An agent handles each conversation in order. A long-running task delays later replies in that same conversation, while separate conversations can continue in parallel.

**The agent doesn't act as me even though I own it.**
The agent must be able to match your Slack identity to your HQ account. Use **Connect Slack** in the agent's settings, or open **Personal Integrations**, and authorize the same workspace the agent uses (see [When the agent acts as you](#when-the-agent-acts-as-you-owner-delegation)). Also confirm you're an active owner in the agent's **Owners** panel, and ask your company owner or HQ support whether the company-level delegation control was disabled. When your identity can't be resolved, the agent acts as itself by design rather than guessing.
